# 出货明细加面图标 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `/shipping-records` 页面"重点"列（改造自"环保"列）对品名含"杂胶" + 规格含"加面"的明细行渲染细密网状 SVG 图标，与环保 🌿 同列显示；整列在整组无环保无加面时隐藏。

## Global Constraints

- **范围限定**：仅 `/shipping-records` 页面；**不动** `inbound-records` / `loading-orders`
- **零后端改动**：渲染条件靠 Jinja 模板字面匹配；不新增字段、不改 schema、不改 Python
- **既存 JS bug 不修**：`shipping-records.html` 行 935/1270/1765/1783 用 `children[1]` 取"品名"实际拿到 eco-col —— 是既存 bug，本期不修（spec §6 风险 1）

- **Tailwind 内联样式风格**：本仓库 Tailwind 类优先；本改动沿用 `.jia-mian-icon` 自定义 CSS 类（与现有 `.eco-icon` 风格一致）

## Task 4: 实现 SVG 图标内联 + 条件渲染

**Files:**
- Modify: `templates/shipping-records.html:437`（eco-col cell）

**Why:** 核心功能——按规格条件渲染加面图标。

**Interfaces:**
- Produces: 同一 cell 内可同时显示 🌿（条件：品名含"环保"）+ 🕸️ SVG（条件：品名含"杂胶" AND 规格含"加面"）

**SVG 设计**（spec §3）：

```html
<svg viewBox="0 0 16 16" width="14" height="14" aria-hidden="true" class="jia-mian-icon" title="加面工艺">
  <defs>
    <pattern id="jm-mesh-{{ loop.index }}" width="2" height="2" patternUnits="userSpaceOnUse">
      <path d="M 2 0 L 0 0 0 2" fill="none" stroke="currentColor" stroke-width="0.5"/>
    </pattern>
  </defs>
  <rect width="16" height="16" fill="url(#jm-mesh-{{ loop.index }})"/>
  <line x1="0" y1="8" x2="16" y2="8" stroke="currentColor" stroke-width="1"/>
</svg>
```

> ⚠️ **pattern id 必须含 `{{ loop.index }}` 唯一化**——SVG `<defs>` 是 document-scoped，同一 id 多次出现会让后定义的 pattern 覆盖前面的，导致所有 SVG 共享同一个 pattern（视觉上仍 OK，但 DOM 合法性差）。后续如有需要可改为 inline 渲染（不用 pattern），但本期先用 index 区分。

- [ ] **Step 1: 定位 eco-col cell 行**

读 `templates/shipping-records.html` 行 437（位于 `{% for item in group.records %}` 循环内），确认原内容：

```html

```

- [ ] **Step 2: 在原 cell 末尾追加条件渲染 SVG**

**只追加**，**不修改**原行内容。改后该行变为：

```html
<td class="eco-col">{% if '环保' in item.product_name %}<span class="eco-icon" title="环保产品">🌿</span>{% endif %}{% if '杂胶' in item.product_name and '加面' in item.specification %}<svg viewBox="0 0 16 16" width="14" height="14" aria-hidden="true" title="加面工艺"><defs><pattern id="jm-mesh-{{ loop.index }}" width="2" height="2" patternUnits="userSpaceOnUse"><path d="M 2 0 L 0 0 0 2" fill="none" stroke="currentColor" stroke-width="0.5"/></pattern></defs><rect width="16" height="16" fill="url(#jm-mesh-{{ loop.index }})"/><line x1="0" y1="8" x2="16" y2="8" stroke="currentColor" stroke-width="1"/></svg>{% endif %}</td>
```

> 注意：SVG 直接内联，**没有 `<span class="jia-mian-icon">` 包裹**——SVG 本身的 `stroke="currentColor"` 已能让 CSS `.jia-mian-icon` 生效。class 加在 `<svg>` 上即可。

修改方法：在原行末尾的 `</td>` 前**插入** `{% if ... %}...{% endif %}` 块。

## Task 5: 实现 `has_jia_mian` 计算 + 整列隐藏扩展

**Files:**
- Modify: `templates/shipping-records.html` 渲染 group 区域（`<table>` 之前）
- Modify: `templates/shipping-records.html:416`（`<table>` class 条件）

**Why:** 现有 `has_eco` 标志决定整列是否隐藏（`.no-eco` 类）。加面出现后，"整组无环保但有加面"的情况会让整列显示但无 🌿——空 cell 不美观。需要扩展为"无环保且无加面"才隐藏。

**Interfaces:**
- Produces: `has_jia_mian` 布尔标志，在 group 渲染时计算
- Consumes: `group.records` —— 每条记录用相同判断逻辑

- [ ] **Step 1: 定位 group 渲染区域**

读 `templates/shipping-records.html` 在 `<table class="record-table">` 之前找 `has_eco` 计算的位置（grep `has_eco`）：

```bash
grep -n 'has_eco' templates/shipping-records.html
```

预期 2 处：table class 条件 + group 构造处。

- [ ] **Step 2: 新增 `has_jia_mian` 标志**

在 `has_eco` 计算**同一处**（通常是 Jinja set 块）**之后**新增：

```jinja
{% set has_jia_mian = group.records|selectattr('product_name', 'match', '杂胶')|list|length > 0
   and group.records|map(attribute='specification')|map('match', '加面')|list|any %}
```

更直白写法（推荐，可读性更好）：

```jinja
{% set has_jia_mian = false %}
{% for r in group.records %}
    {% if not has_jia_mian and '杂胶' in r.product_name and '加面' in r.specification %}
        {% set has_jia_mian = true %}
    {% endif %}
{% endfor %}
```

> 注：Jinja 的 `{% set %}` 在 for 循环里是块作用域，第二种写法需用 namespace 或外层 set。建议用 `namespace()`：

```jinja
{% set ns = namespace(has_jia_mian=false) %}
{% for r in group.records %}
    {% if not ns.has_jia_mian and '杂胶' in r.product_name and '加面' in r.specification %}
        {% set ns.has_jia_mian = true %}
    {% endif %}
{% endfor %}
{% set has_jia_mian = ns.has_jia_mian %}
```

实际选择：保持与项目现有 `has_eco` 风格一致。先看 `has_eco` 怎么写的：

```bash
grep -B1 -A1 'has_eco' templates/shipping-records.html
```

- [ ] **Step 3: 改 `<table>` class 条件**

定位行 416（或 grep `not has_eco` 找到准确行）：

```html
<table class="record-table{% if not has_eco %} no-eco{% endif %}{% if not has_match %} no-match{% endif %}">
```

改为：

```html
<table class="record-table{% if not has_eco and not has_jia_mian %} no-eco{% endif %}{% if not has_match %} no-match{% endif %}">
```

**只改 `not has_eco` → `not has_eco and not has_jia_mian`**，其他字符不动。

> 注：class 名仍叫 `no-eco`（沿用），因为它实际现在控制"无重点"——改名会牵动 CSS 类名（spec §6 已说明 class 保持稳定）。如要更准确可改名为 `no-key`，但要同步改 `.no-eco { display: none }` CSS 选择器，**本期不做**。

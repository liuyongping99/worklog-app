## 4. 影响评估（针对后续 Task 2-5）

### 4.1 本次实施（加面图标）的直接风险

**新增图标会让 4 处"伪品名"内容更乱**：

| 之前 | 之后（环保 + 加面） | 之后（仅加面） |
|---|---|---|
| `""`（空）或 `"🌿"` | `"🌿🕸️"`（或 SVG 文本节点内容） | `"🕸️"`（或 SVG 文本节点内容） |

具体后果：
- **站点 1 / 3 / 4**：`pn` 传给 `addRowWarning` 的 `product_name`。`addRowWarning` 可能拿这个串去匹配"环保" / "杂胶" / "加面"等关键词做警告决策，导致**警告显示/隐藏**可能异常。
  - 注意：现在的 eco-col 只渲染 `"🌿"` 一字（emoji），关键字匹配 if `'环保' in pn` 命中的是 emoji 文本而非"环保"二字——也就是说，**站点 1/3/4 当前大概率不命中任何环保警告**（已存在的静默 bug）。
  - 加面图标引入后，eco-col 文本节点新增 SVG 节点，**`pn` 内容变化但仍不命中任何业务关键字**（因为关键字是品名级别的，不是 emoji/SVG 级别），所以警告行为大概率仍保持"静默不命中"——视觉上无回归。
- **站点 2**：`productName` 传给 `appendOrderImageArea`，叠加到上传图片的 alt/展示。如果图片区对 `product_name` 字段有显式渲染，会显示 `"🌿🕸️"` 之类的伪品名。但实际多数情况为空串或 `"🌿"`，需要核对 `appendOrderImageArea` 的渲染逻辑（**本次不深查**，仅记录为风险点）。

### 4.2 实施者须知（Task 2-5 必读）

1. **不要修改这 4 处代码**——属于 spec 明确排除的技术债，本期范围只动模板列头/Jinja 渲染/CSS。
2. **实施后做一次目测验证**：
   - 创建一个"环保加面杂胶"明细 → 视觉确认 🌿🕸️ 横排显示
   - 锁定/解锁该订单 → 确认 JS 控制台无报错，且 `addRowWarning` 行为不变
   - 上传一张图片 → 确认图片区不显示异常品名（即 `pn` 取错的影响范围可控）
3. **如果发现视觉/功能回归**（例如 addRowWarning 渲染错位、警告行异常出现），**回滚 spec 范围，回到本审计讨论**：可能是站点 1/3/4 的 bug 之前隐藏，现在被加面图标"激活"了。
4. **站点 2 的 specification 索引也错**（`tds[2]` 应是 `tds[3]`）—— 这是个**额外的潜在 bug**，spec 未列入风险清单，但本审计实测发现。如果实施者动图片上传相关逻辑时遇到奇怪行为，**先怀疑这里**。

### 4.3 是否需要"补丁式修复"？

**结论：不建议**。
- 4 处 bug 是既存技术债，spec 明确"本期不修"。
- 修这 4 处需要重测 `addRowWarning` / `appendOrderImageArea` 的所有调用路径，超出本期范围。
- 加面图标的 JS 改动 = 0（纯 Jinja 模板渲染 + CSS），理论上不会激活新 bug。
- 风险等级：低（"警告静默不命中"已存在；本次仅让"伪品名"内容多一个 emoji/SVG 节点）。

## 5. 未来重构建议

**用 `.product-name-cell` class 选择器替代索引访问**——代码库里已经有 2 处正确示范：

- `templates/shipping-records.html:1331` — `var nameTd = tr.querySelector('.product-name-cell');`
- `templates/shipping-records.html:1590` — `productName = ((row.querySelector('.product-name-cell') || {}).textContent || '').trim();`

**重构方案**（不在本期做）：

```javascript
// 改前
var pn = (tr.children[1] && tr.children[1].textContent || '').trim();
var sp = (tr.children[2] && tr.children[2].textContent || '').trim();

// 改后
var pn = ((tr.querySelector('.product-name-cell') || {}).textContent || '').trim();
var sp = ((tr.querySelector('.spec-cell') || {}).textContent || '').trim();
```

**配套修复点**：
- 站点 1/3/4：同时修 `sp` 索引（应改用 `.spec-cell`）
- 站点 2：`productName` 用 `.product-name-cell`，`specification` 用 `.spec-cell`
- 加 `.product-name-cell { }` 明确标记语义类，便于后续 lint 检查

**收益**：
- 抗列顺序变化（未来如果新增/调整列，不再踩坑）
- 抗 eco-col 内容变化（加面图标、加特硬图标都安全）
- 自我文档化（class 名即语义）

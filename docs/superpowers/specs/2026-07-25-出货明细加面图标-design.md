# 出货明细加面图标 — 设计文档

- 日期：2026-07-25
- 页面：`/shipping-records`
- 路线图定位：阶段 2「AI 验数 + 校对」的视觉补充；让规格属性在明细行能"一眼看到"
- 状态：待用户 review

## 1. 背景与目标

出货明细的规格列当前是纯文本，但规格里实际包含一些需要**重点核查**的属性 token：

- **加面 / 中性加面 / 双面**（工艺属性，影响价格 6~10y/支的差异）
- 厚度（3mm / 5mm 等，影响用途）
- 颜色（黑/白/红/蓝等，影响订单对色）

这些属性一旦录入错误（"加面"录成"单面"），后续装车/对客户都会出问题。

### 目标

在出货明细表格的"重点"列（改造自现有"环保"列）增加**加面工艺图标**（细密白色网状物 SVG），与现有环保 🌿 同列显示，让规格中的"加面"属性在视觉上一眼可辨：

| 规格条件 | 显示 |
|---|---|
| 品名含"环保" | 🌿 |
| 品名含"杂胶" **且** 规格含"加面" | 🕸️ SVG（细密网状） |
| 两者都满足 | 🌿 + 🕸️ 横排 |
| 都不满足 | 空格 |

整列在**所有明细都不满足条件**时整列隐藏，沿用现有 `.no-eco` 机制。

### 非目标（明确排除）

- 不新增其他属性图标（厚度、颜色、特硬等）—— 范围控制为只加"加面"，避免一次性扩张
- 不改 `inbound-records` / `loading-orders` —— 本期只动出货页
- 不做规格文本的自动修正（如把"单面"自动改成"加面"）—— 只做视觉标识
- 不做后端字段映射 —— 渲染条件靠前端 Jinja 模板字面匹配，零后端改动

## 2. 列名重构："环保" → "重点"

把现有 `<th class="eco-col">环保</th>` 改为 `<th class="eco-col">重点</th>`，含义从单一属性升级为**属性类别**：

- ✅ 容纳 🌿（环保认证）+ 🕸️（加面工艺）两个不同维度的属性
- ✅ 为未来加"特硬""网纱"等图标预留位置，列头不需要再改
- ✅ 业务语义：这两个属性都是出货环节需要**重点核查**的关键属性

class 名仍叫 `eco-col`（CSS 类名稳定，避免连锁改动），仅 HTML 文本变。

## 3. 图标设计

### 形态描述

**细密白色网状物** —— 模拟织物背面的网格（"加面"工艺即在面料背面加一层织物）。

```
viewBox="0 0 16 16",渲染 14x14 px
  - 外框圆角矩形(可选)或无框
  - 内部细密网格:横线 + 竖线,线宽 0.5px,间距 1.5px,共 ~8x8 = 64 格
  - 中间略粗 1 条横线表示织物底布(线宽 1px)
  - stroke 颜色 = currentColor(由 CSS .jia-mian-icon 决定)
```

### 实现：内联 SVG

```html
<svg viewBox="0 0 16 16" width="14" height="14" aria-hidden="true">
  <defs>
    <pattern id="jm-mesh" width="2" height="2" patternUnits="userSpaceOnUse">
      <path d="M 2 0 L 0 0 0 2" fill="none" stroke="currentColor" stroke-width="0.5"/>
    </pattern>
  </defs>
  <rect width="16" height="16" fill="url(#jm-mesh)"/>
  <line x1="0" y1="8" x2="16" y2="8" stroke="currentColor" stroke-width="1"/>
</svg>
```

- 内联在 `shipping-records.html` 的 cell 里，**不外置 SVG 文件**（保持单文件改动）
- pattern id 用 `jm-mesh`（jia-mian mesh）避免与可能的环保图标冲突
- CSS `color: #868e96` 透传到 `stroke="currentColor"`

### 颜色

| 图标 | 颜色 | 语义 |
|---|---|---|
| 环保 🌿 | `#2d8c4a`（已有） | 认证属性 |
| 加面 🕸️ | `#868e96`（中性灰） | 工艺属性 |

颜色分离让"环保+加面"双图标时也清晰可辨，不混淆。

## 5. 边界情况

| 场景 | 行为 | 原因 |
|---|---|---|
| 品名含"杂胶" + 规格含"中性加面" | ✅ 显示 | "加面"是子串，"中性加面"包含"加面" |
| 品名含"杂胶" + 规格含"双面" | ✅ 不显示 | 字面匹配，"双面"不含"加面"两字（与 OCR 等价规则分开，避免误判） |
| 品名"环保纯胶" + 规格含"加面" | ❌ 不显示 | 不含"杂胶" |
| 品名"加面杂胶" + 规格含"加面" | ✅ 显示 | 品名和规格都含 |
| 品名含"杂胶" + 规格空 | ❌ 不显示 | 规格无"加面" |
| 加面非环保（仅 🕸️） | 仅 🕸️ 显示，行**不**触发 `.row-eco` 绿色底 | 行底色语义保持"环保"专属 |
| 规格被 JS 编辑保存后 | 需刷新页面才更新图标 | 后端模板渲染自然限制（已知 trade-off） |
| 整组无环保也无加面 | 整列隐藏 | 沿用现有 `.no-eco` 机制 |
| "加面"出现在备注列（非规格） | ❌ 不显示 | 只判断 `item.specification`，不判断备注 |

## 6. 风险与缓解

| # | 风险 | 严重度 | 缓解 |
|---|---|---|---|
| 1 | **既存 JS bug**：`shipping-records.html` 中 4 处（行 935、1270、1765、1783）用 `tr.children[1].textContent` / `tds[1].textContent` 取"品名"，但 children[1] 实际是 eco-col（td 序号：0=序号、1=eco-col、2=product-name-cell）。改前拿到的可能是 "🌿" 或空串，导致 `addRowWarning` 用的 `pn` 错误。加面图标改动不引入新 bug，但让这 4 处拿到的"伪品名"内容更乱（"🌿🕸️" / SVG 内文本）。 | 中 | **本 spec 不修这个 bug**（属于既有技术债，超出范围），但实施时要实测确认视觉效果无回归；如未来重构 JS，建议改用 `tr.querySelector('.product-name-cell').textContent` |
| 2 | 编辑规格后图标不立即更新（要刷新） | 低 | hover tooltip 提示用户刷新；后续如有需求再补 JS 端渲染 |
| 3 | SVG 在低 DPI 屏幕模糊 | 低 | viewBox 16x16 + width=14 + stroke-width=0.5，是 SVG 设计的标准最佳实践 |
| 4 | 整列宽度 35px 容纳两个图标略显挤 | 低 | inline-block + margin-left:2px，实际占用约 32px（🌿 14px + 间距 2px + 🕸️ 14px），可容纳 |
